# Поток авторизации клиента

1. Клиент получает access token от `auth-service`.
2. Клиент хранит token в выбранном безопасном хранилище платформы.
3. Защищённые запросы отправляются с `Authorization: Bearer <token>`.
4. При `401` клиент обновляет token через auth flow.
5. При `403` клиент скрывает действие или показывает сообщение о недостаточных правах.

## Пример

```bash
curl -H "Authorization: Bearer ${TOKEN}" \
  http://localhost:8082/podcast/v1/users/me/profile
```

## Ролевой UI

| Роль | UI действия |
|---|---|
| `user` | плейлисты, голоса, подписки, история |
| `author` | авторский кабинет, создание подкастов |
| `admin` | управление категориями |

## Становление автором

Кнопка перехода в роль автора вызывает существующий endpoint `POST /authors/me` с текущим пользовательским token. В ответе клиент получает новый `access_token`, `expires_in` и `author_profile`. После успешного ответа клиент заменяет сохранённый access token на новый и открывает авторский кабинет.

Повторный вызов безопасен: если author profile уже существует, сервис возвращает существующий профиль и новый token.
