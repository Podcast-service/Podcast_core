# Поток HTTP-запроса

## Общий путь запроса

1. Запрос приходит в приложение под servlet context path `/podcast/v1`.
2. CORS policy проверяет origin браузерного клиента.
3. `JwtAuthenticationFilter` извлекает `Authorization: Bearer <token>`.
4. JWT валидируется по алгоритму `HS256`, issuer, expiration и подписи.
5. Spring Security применяет route-level правила и `@PreAuthorize`.
6. Контроллер валидирует параметры и тело запроса.
7. Сервисный слой выполняет бизнес-проверки и операции с БД.
8. DTO возвращается клиенту или исключение преобразуется в `ApiErrorResponse`.

## Публичные запросы

Публичные GET-запросы доступны без токена. Если токен передан, сервис использует его для персонализации полей:

| Поле | Пример |
|---|---|
| `currentUserVote` | голос текущего пользователя за подкаст или плейлист |
| `progressSeconds` | прогресс прослушивания текущего пользователя |
| `isSubscribed` | признак подписки на автора |

## Защищённые запросы

Защищённые операции требуют JWT. Для ролевых операций используются роли из claim `roles`.

| Роль | Примеры операций |
|---|---|
| `user` | профиль, плейлисты, голосование, подписки, история |
| `author` | создание и управление авторским профилем, подкасты |
| `admin` | управление категориями |

## Транзакционные границы

Транзакции находятся в сервисном слое. Операции изменения плейлистов, голосов, подписок и истории выполняются атомарно в пределах соответствующего service method. Обновление счётчиков выполняется синхронно с изменением связи или голоса.

## Ошибки

| Сценарий | HTTP статус | Код |
|---|---:|---|
| отсутствует или невалидный токен | `401` | `UNAUTHORIZED` |
| роль не подходит | `403` | `FORBIDDEN` |
| ресурс не найден | `404` | `RESOURCE_NOT_FOUND` |
| конфликт уникальности | `409` | `CONFLICT` |
| нарушение бизнес-правила | `422` | `BUSINESS_RULE_VIOLATION` |
| непредвиденная ошибка | `500` | `INTERNAL_ERROR` |
